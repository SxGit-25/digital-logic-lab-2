# 统一扫描合约审计

基线：`f4507a821c26b647131a962522dd61b9be2676c3`。本次仅读生产 RTL；没有改生产 RTL 或现有测试预期。`baseline_evidence.txt` 记录基线源码行号和 SHA256，`phase_timing.csv` 为独立理想事件模型，不是逐周期 RTL 仿真；实际还受寄存器握手和毫秒 tick 相位影响。

## 无法同时精确保持的要求

1. **1ms 步进与 20ms PWM。** 原 servo 只在 20ms 帧边界锁存新命令。45 个逻辑 1deg 步可以在 45ms 内计算完，但标准帧只能输出其中两三次命令；不能声称舵机实际走过45个、间隔1ms的独立角度位置。若45个位置都各输出一帧，命令序列至少占900ms。直接帧内改比较阈值则改变 PWM 波形，并可能截短或重新拉高当前脉冲，不能保持旧 basic PWM 行为。

2. **停后稳定300ms与旧采样时刻。** 旧 basic 在新目标由 PWM 锁存、`angle_applied` 反馈后稳定300个毫秒 tick，再触发测距。若45ms逻辑快走后等待最终 PWM 命令实际锁存，再完整稳定300ms，采样必然后移。五种帧相位的理想模型显示相对旧采样延后40ms或60ms；若只从逻辑停步开始算则约45ms。保留旧触发时刻会把实际最终命令稳定时间缩短为240ms或260ms，不能仍称300ms。

3. **停后更新数码管与旧 basic 显示。** 旧 `display_compose` 直接由 `angle_idx` 生成角度，`radar_ctrl` 在2s槽边界立刻切换 `angle_idx` 并清 `current_valid`。因此旧显示在槽边界即变成新角度及距离横杠。若新角度必须等45ms停步或最终 PWM 锁存后才显示，至少角度字段的外部时序必然改变。还需明确距离字段是在槽边界立即横杠，还是移动时保留上一笔；后者也改变旧行为。

4. **采样改变与距离/历史/报警的逐周期等价。** 延后触发后，任意变化的 echo 输入可能得到不同有效性和距离，进而改变数码管、历史矩阵和报警，不可能保证这些输出对任意输入仍与旧版逐周期相同。即使给定相同的测量结果，结果提交和报警开始时间也会后移；报警节奏由 `current_valid` 清零重新计时，无法无条件保持旧相位。可保持规则、阈值和样本次序，不能同时保持完整事件时序。

5. **1deg逻辑步与原连续扫描轨迹。** 原连续模式每20ms改变5us脉宽，400帧/8s单程，BCD显示是0.45deg步进累积后的四舍五入值。新1deg/60ms是180步/10.8s单程，原801帧期望明确不再适用。500..2500us的180个1deg间隔要求每步100/9us；整数微秒 PWM 只能按11/12us误差累积逼近，BCD可严格1deg，不能把每个物理脉宽称为数学上精确1deg。

## 最少待确认项

1. **步进的含义与 PWM 应用边界：** 允许1ms逻辑快走、20ms帧边界应用最新命令，并允许1deg目标用11/12us累积量化吗？这能保持正常 PWM 帧，但中间45步不会逐个成为独立舵机脉冲。
2. **basic时序优先级：** 建议固定2s槽、最终命令应用后稳定300ms再测；允许采样/历史/报警及停后角度显示相对旧版后移。距离字段建议仍在槽边界清为横杠、移动中不显示中间角度；这是明确的新显示行为，不能再要求这些事件与旧 basic 逐周期相同。若坚持旧采样时刻，就必须明确接受缩短稳定时间。
3. **起点/端点与回归合约：** 建议 basic 保留首次0deg整整2s槽（该槽无需45步快走），目标序列 `0,45,90,135,180,135,90,45,0,45,...`；连续模式可在进入RUN时先测0deg，以后每60ms先步进再测，端点只测一次并采用向外离开端点的方向标记。是否接受此定义，并授权仅因新合约必需而调整受影响测试预期？若连续首次必须仍在60ms才测，则首个测角是1deg，0deg仅待下次返回时测；不能两者兼得。

## 可保持且不需要新取舍的部分

- 开关消抖、关机立即禁用、上电复位、2s自检和2s待机可保持。模式切换仍取消测量并重新进入启动流程。
- basic 每2s槽边界及目标次序、每槽最多一次测距、未完成结果的槽末失效处理可保持；首0deg槽保留后，初次测距仍可在RUN后约300ms进行。
- 超声波触发长度、同步、毫米换算、回波有效范围、超时和取消机制可保持。
- 数码管扫描/消隐及解码、矩阵扫描电气时序与布局、距离分级阈值、颜色映射、蜂鸣器载波/节奏规则可保持；但由新测量时刻驱动的数据更新时刻不保证旧等价。

## 原六套回归的影响

原 runner 为 `servo_pwm / ultrasonic / radar_ctrl / radar_top / alarm_ctrl / counter_equivalence`。

- `ultrasonic`、`alarm_ctrl`、`counter_equivalence` 可保持原期望，前提是不改变各自原接口/子模块规则。
- `servo_pwm` 原测试把中途45deg命令视为下一帧直接应用1000us。若默认 basic 命令改为45步快走，这一期望需变；若旧接口保留为独立兼容模式，该测试可以原样通过，但不能代替新统一扫描测试。
- `radar_ctrl` 含与旧 baseline 全输出逐周期比较，新快走/延后采样/显示握手不满足原等价合约；其缩时配置 `SLOT_MS=8, SETTLE_MS=1` 也容不下固定45ms快走。
- `radar_top` 缩时配置 `SLOT_MS=10, SETTLE_MS=1` 同样容不下固定45ms。应新增可缩放的步进时间参数或扩大仿真时隙；调整前需用户确认合约，不能通过悄改期望掩盖差异。
