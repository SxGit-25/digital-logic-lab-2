# 1458 / 1415 LE 候选与压缩方案

本轮只核对资源、记录验收更新和提出方案，不修改 RTL 或原回归预期。后续优化以直接 BCD 测距的 1415 LE 候选为工作基线；采用为最终版本仍须满足测距与整机回归条件。

## 实测资源与计数口径

逐模块展开：

- 测距：二进制 ultrasonic 157 + bin12_to_bcd 82；BCD ultrasonic_bcd_experiment 198，无后置转换器。
- 统一扫描：radar_unified_scan 298 / 291，已包含单套角度、方向、PWM、调度、5 线历史与距离等级逻辑，无第二套 radar_ctrl/servo_pwm。
- LCD：lcd_bus 103 / 103，lcd_init 80 / 79。
- 绘图：微序列控制器自身 205 + minsky_serial_registers 112 = 317；后者含 80 个寄存器，整个绘图含 140 个寄存器。
- 顶层其余：外层 wrapper 1 / 1，system 自身 69 / 70，reset_ctrl 8 / 8，SW6 filter 11 / 11，SW7 filter 12 / 12，timebase 39 / 39。system 内混有接口选择、输出门控与请求组合逻辑，不能全部标成模式 mux。

**绘图未达到 ≤200 LE：整机上下文 317 LE，超出 117 LE。** 已使用 Minsky 正逆旋转、无 sin/UFM、无请求队列、单微序列状态机和一个位串行加法数据通路；控制计数器、phase 调度、BCD→角度组合转换仍有各自算术逻辑，不能称整个子系统所有算术只用一个加法器。独立绘图工程为 328 LE，与整机 317 属不同优化上下文，不混用。

两整机均 75 I/O、UFM 0；1458 超器件容量 188 LE，1415 超出 145 LE。以新预算计算，BCD 基线还需省至少 145 LE 才可能装入 1270，省 272 LE 才达到优选 1143；最终必须 Fitter 成功并通过时序，setup slack 目标至少 1 ns。默认禁读的 992 LE BCD 版虽成功，但只有初始化清屏，不能作为完整极坐标验收结果。

## 最大三类的架构方案（未实施）

以下预计为工程判断区间，不是 Quartus 实测，不作可相加的承诺。每项应由同一整机配置独立编译，再编译合并配置；保留端区批量、1°、后方命中 0 和默认禁读。

| 优先级 / 当前 LE | 架构调整 | 预计净节省 LE | 核验重点 |
|---|---|---:|---|
| 1 绘图 / 317 | 将控制和参数算术继续串行化：BCD 角度转换、±10°、phase 和旋转微步计数复用微指令操作数/计数寄存器；向量与射线寄存器采用固定移位路径，减少多路装载与旋转选择；把 RMW 事务推进编码进同一微程序，删除独立 pending/transaction 推进选择链。 | **70～120**，目标约 197～247 | 现控制自身205，数据通路112，不能只再串行 ALU；需同时压控制。可减少周期冗余，但更深串行可能拖慢速度；普通请求 <1ms、端区时限和全角误差必须重验。达到200需落在区间上端，不能保证。 |
| 2 扫描引擎+ctrl / 291 | 用一套事件调度组织启动、基本槽、连续步进及稳定等待；在互斥阶段复用计数器和状态。以公共时间基准生成帧/时隙事件，削减独立比较与更新链；5线历史改为共享写数据/写使能译码，距离等级集中一次产生并分发，削减测距模块与ctrl重复阈值网络。 | **25～45**，目标约 246～266 | 保持 720µs 快走、旧目标PWM保持、2s槽、60ms连续和取消语义。公共计数器须在同源对齐被证明后才替换，不能把不同复位域计数器直接短接。跨测距边界的等级共享收益归本项，第三项不重复计。 |
| 3 测距 / 198 | 工作BCD/提交BCD/ctrl显示BCD明确为工作值与唯一已提交快照两份，去掉中间提交副本；提交时由ctrl接收稳定工作值。trigger与echo预算在互斥阶段共用计数/比较网络；检查半径余数、1200越界状态与已有BCD状态是否可合并。 | **10～20**，目标约 178～188 | 先证明done、取消、noecho、饱和、结果保持时序；不得让计数中的BCD直接出现在数码管。精确170kHz分数相位在echo边沿重置，与公共1MHz计数器不同步，不能简单合并或改成/294。 |

建议先做绘图，因为它有最大可见控制开销。若绘图恰到200，整机在其他逻辑不变的假设下仍约1298，仍需至少28 LE的额外压缩；这只是资源缺口分析，不是合并编译结果。上述区间机械相加为105～185，算术上对应1230～1310，因此它们**尚不足以保证1270，更不能承诺1143**。不把显示三类合并优化加入本轮前三项，避免同时扩大改动范围。

字节合并能减少端区总线访问，但需要缓存/比较，未证明节省LE，本轮不把它计入上述面积收益。现端区最坏2.544740ms仍是未通过项，不能以方案预计面积代替时限验证。

## BCD 基线的前提与已有证据

用户已指定1415候选为后续优化基线。本轮按此选择开展方案分析，不将条件性采用写成最终回归通过。

- 相对 f4507a8，精确170kHz直接BCD在双方有效样本中最大差1mm，94.30115%相同；独立RTL仿真7,438,473周期、13场景×4策略通过，trig/busy/done与旧测距逐周期一致。
- 边界语义存在实际差异：75,000,000例中，14,100例旧版无效而BCD有效；双方有效样本中等级边界3,520例、25mm半径bin 39,306例、1200mm半径valid 781例不同。这些可能改变报警/点阵，不能只凭“误差≤1mm”宣称原外部行为全部一致。
- 原六套基础回归通过针对保留的旧模块。当前新顶层readback0/1联调通过也使用默认二进制测距，不能冒充直接BCD整机回归。
- 后续BCD版须补整机回归，逐条说明数值量化导致的边界预期差异；未确认前不静默修改旧预期。若原有效范围须严格保持，则另行设计兼容判定并实测新增LE，不能预先视为零成本。

## 稳定计时与新验收约束

按本次更新，首选方案1：目标PWM实际应用后300ms测距，默认首0°槽+300ms、后续槽+320ms。若与方案2同源整机编译相比多出 **>2 LE**，选择方案2：保持槽+300ms测距，并记录点阵外部可见差异上限 **28ms**。恰好多2LE仍用方案1。

本轮依“先报告方案，不要直接改”暂停实现；当前1458/1415快照仍是槽+300ms，方案1的LE增量尚未实测，因此不宣称已恢复稳定计时或已满足≤2LE条件。后续对比必须使用BCD整机、相同Quartus选项及相同其他RTL，分别报告总LE/寄存器/Fitter/时序；不能用独立模块差值或源码行数替代。

已有原点阵RTL反例证实提前20ms提交可使可见变化提前23.25ms，解释了恢复旧计时的必要性。方案2的28ms是用户新授予的验收上限，尚非全相位实测最大值；需要验证20ms采样差+8ms点阵周期的上界及临界同拍行为。
