## 实现

- ray_engine：单张 91 项 Q1.8 表（1.0=256），分时查 sin(theta)、sin(90−theta)。幅值累加器为无符号 Q6.8；仅在输出坐标时四舍五入。0..3 步内部行进但不输出，4..48 步输出；90..180° 反转 x，MIRROR_X 统一水平镜像。无运行时乘法、除法或取模。
- radar_lcd_ctrl：接受一次请求时锁存角度、方向、半径和有效位；先 A 后 B，越界的提前擦除整步跳过。忙时不接收新请求。r<4 或 r>48 不画目标，valid=0 不画目标，距离圈仍画。
- 每像素八笔事务：页、列高、列低、空读、真读、恢复列高、恢复列低、写修改字节。普通读使列地址递增，写回前必须恢复原列；一次 RMW 期间页地址不变。掩码为 1<<y[2:0]，页 y[5:3]、列 x。未使用 E0/EE，不依赖其列地址行为。
- P1 的 lcd_bus、lcd_init 和基础雷达模块均未修改。新增 lcd_p2_core 调度初始化与绘图总线所有权；顶层自动 0→180→0、半径 8..44、每次请求间隔不少于 20 ms，LED 输出当前命令角度。测试激励不代表实际舵机或超声波输入。
- UFM 使用真实 altufm_none，512×16 MIF 的高9位存系数，低7位填1。Quartus 实际占用 UFM=1，未误综合行为模型。完整说明见 source/lcd_p2/ufm_notes.md。

## 误差与验证

全部 181×49=8869 个角度/半径组合，对称圆整浮点参考的最大单轴误差 1 像素：8435 个为 0，434 个为 1（206 仅 x、228 仅 y）；对未取整浮点最大单轴误差 0.5830331204 像素、最大欧氏距离误差 0.7364662031 像素。case/UFM/镜像共验证 26607 组；case 和 UFM 逐点一致。Q1.8 单系数量化误差 ≤1/512，48 步累计量化误差 ≤0.09375 像素/轴，最终坐标还含整数取整误差。

case 和 UFM 各跑 596 次更新、26245 个像素 RMW、209960 笔总线事务，每次更新后全部1056字节显存与独立参考一致。包括完整往返、多个目标后换向、边界半径、无效半径、反压、忙时请求、输入锁存和默认关闭回读。三个真实显存 PBM 在两种方案间 SHA256 一致。UFM91项串行测试另检查 609..640 主时钟周期延迟、串行建立保持及周期的30%余量；注入180ns输出稳定延迟。六套现有雷达回归全部通过。

已人工查看真实显存 PNG：圆心在底中(64,63)，最高圈到y15，页0留白，图形左右方向正确；没有填补缺点。图像来自 PBM 的最近邻放大，见 simulation/。

最小实测复现：先画 172°、r=26 的目标，其位置为(38,59)；随后 k=180 方向下降，A 擦除170°的n=26，也落在(38,59)，清掉该目标。由 UFM＋真实LCD总线模型复现，前后图为 alias_before/after.png。

596次独立参考更新中出现29次涉及其他射线目标的擦除事件、119次涉及圈像素的擦除事件。完整往返三圈点亮率依次65/65、112/113、149/149，r32缺(96,57)。多目标换向为64/65、111/113、149/149，缺(53,52)、(41,40)、(43,38)。各圈仍为一个8邻域连通分量，但不能据此宣称完全无误擦。

这些结果与指定 A/B 算法精确一致；“只跳过当前擦除射线的第16/32/48步”和“邻线目标绝不误擦”在单比特像素重合时无法同时保证。当前交付保持已定算法。是否接受这种栅格重合限制，或允许调整算法/保存额外信息，需要用户决定；任何改法均须重新仿真并实测资源。不得把该项报告成通过。

## 时序核对

三个工程最终 TimeQuest 均为0 errors/0 warnings，setup/hold未约束时钟、输入输出端口及路径均为0。case/UFM全编译均0 errors/21 warnings，均为常量宽度截位；默认参数数值可容纳（theta≤90、帧计时999999、初始化计时999999），未屏蔽警告。safe共32 warnings，额外为OE始终使能和RD恒高等符合默认安全策略的常量端口。原始日志保留。

UFM生成时钟周期640ns，高低各320ns；ARCLK/DRCLK setup slack分别299.206/298.040ns，hold最小各60ns。详细报告实际匹配9个系数捕获寄存器、1个UFM串行寄存器、1个UFM地址寄存器；串行数据至系数捕获setup/hold为610.063/9.383ns。没有宽泛false path。完整例外依据见 source/lcd_p2/ufm_notes.md。

LCD输出约束max=5ns/min=0。回读max=110ns：14ns clock-to-RD预算 + 70ns访问×1.3 + 5ns板级预算；min=0。仅对8个read_data寄存器使用setup9/hold8多周期，UFM方案实际LCD输入setup/hold最小67.767/1.055ns。Fitter LCD Tco范围：case 9.005..12.534ns，UFM 9.028..12.815ns（含RST在内的保守包络），因此RD Tco低于14ns预算。

按UFM最坏全LCD引脚延迟差3.787ns再加5ns板级差值估算，写低120ns最低111.213ns≥104ns，读低200ns最低191.213ns≥182ns，写建立80ns最低71.213ns≥52ns，恢复120ns最低111.213ns≥104ns。连续事务还必须经过ready/done握手，最短同类写下降沿间隔至少340ns（当前P2调度为360ns），保守减8.787ns后仍331.213ns≥312ns。320ns是事务内部状态长度，不能漏掉握手间隔而直接当成实际周期。行为模型在完整仿真中逐笔检查这些下限。

上述板级5ns为约束假设，仍需上板确认；未执行示波器测量、回读电气安全确认及实物验收，不能把内部slack或仿真当作实物签核。

## 复现与上板边界

仓库根目录：

```powershell
powershell -ExecutionPolicy Bypass -File radar/lcd_p2/compile.ps1
powershell -ExecutionPolicy Bypass -File radar/sim/lcd_p2/run_sin_lut.ps1 -IverilogBin <Icarus的bin目录>
powershell -ExecutionPolicy Bypass -File radar/sim/lcd_p2/run_p2.ps1 -IverilogBin <Icarus的bin目录>
```

compile脚本复制到ASCII临时目录，使用SUBST避开Quartus中文路径问题；三种工程全部保留报告，即使失败也保留日志。额外timing_details报告验证LCD和UFM例外实际匹配；Critical Warning、集合未匹配、忽略约束被当作失败。不会自动烧录。

ENABLE_READBACK=0的默认顶层只清屏；read_test两份POF均未经硬件授权。继续沿用P1上板清单：模块稳压及控制器供电、实验板缓冲/电平转换或串联保护、受保护的FF回读电平与示波器波形，确认后才能下载回读测试。当前没有修改任何通用默认值。

P3仍须用户确认阶段推进，以及基本模式/连续模式如何并存。MAX II实际生成.pof，原需求的“两份.sof”在本器件上应为两份独立.pof；也可另选拨码切换，但需确认后再实现。
