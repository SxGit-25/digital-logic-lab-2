# P2 独立验证（MIN_RADIUS=6 / 端区批量擦除修订）

从仓库根目录运行 `powershell -File radar/sim/lcd_p2/run_p2.ps1`。
脚本复制 RTL 与测试平台到 ASCII 临时路径后编译运行；可用 `-IverilogBin`、`-Stage`、`-Results` 指定工具、临时目录及结果目录。原版 RTL 从 Git commit `3231197` 只读提取，仅用于复现对比。

- `tb_ray_engine.v` 同时验证 case、UFM、镜像三种射线，覆盖 181 角度 × 49 半径。步 0..5 观察 WALK 内部坐标，步 6..48 检查 valid/ready 输出；额外检查反压稳定、非法角、复位中止和角度输入锁存。
- `verify_p2.py` 独立生成 Q1.8 参考操作，比较未取整 Python 浮点与对称取整参考，生成误差分布、完整预期显存和精确 PNG（仅标准库）。目标半径 0..5 夹到 6，>48 或 valid=0 不画目标；圆圈保持16/32/48。
- `tb_lcd_p2.v` 不使用 DUT 内部射线坐标做 expected。每次接受 lcd_bus 操作，检查独立像素流中的页/列、空读、实读、恢复原列和修改字节写回；每次更新后逐字节对照全部 1056 字节真实 ST7565 模型 RAM，包括不可见列和相邻像素。case/UFM 各运行 602 次更新，含完整 0→180→0、端点立即换向、输入锁存、忙期间忽略请求、r=0/1/3/4/5/6/7/48/49/63、valid=0、多目标及换向。端点批次各含11射线，fixture 更新计数使用16位。
- P1 `st7565_model.v` 负责真实页列自增、空读、延迟读、三态冲突和总线时序检查。默认关闭回读实例在整个仿真中始终 OE=1、/RD=1，拒绝绘图请求。
- `tb_lcd_endpoint.v` 用原版与新版 UFM 实现/真实总线跑正常单步 `170→180→174`。去程 r20，返程 r35。原版174°射线同时保留旧r20=`(44,61)`与新r35=`(29,59)`；修后端区batch使旧点清零、新点保留。该旧点不与 B180 正当重画的 `(44,63)` 混淆。真实显存分别为 `endpoint_turnaround_original.pbm/png`、`endpoint_turnaround.pbm/png`。
- `exhaustive_erase.py` 独立穷举后方保护规则，输出 JSON 定义及所有命中 CSV。默认 m6 是恰好无命中的最小值：m4 原始半径事件488、按有效半径去重168；m5 为528/88；m6 为0/0。m4/m5 最小原始r均0（夹到m），最小有效r分别4、5。

“后方受保护目标”定义：当前 k，up 时 a<k，down 时 a>k，且未来10个实际1°移动位置（包含端点反向）不访问目标角 a。目标原始半径遍历0..48，有效半径=max(m,r)。擦除角为 k±10；k180/down 批量170..180，k0/up 批量0..10；擦除步 m..48 跳过16/32/48。CSV 的一行是一笔擦除操作命中一个角度与原始半径目标的事件；effective计数去掉原始半径维度，不将夹到同一点的多个原始半径重复算作独立有效目标。

前方即将重扫区域的旧点清除属于预期行为，端点按新方向判断。旧172°r26在k180/down时被170°擦线命中，属于前方计划清除，不再作为本轮验收缺陷。后方保护不承诺保留所有距离圈取整像素：严格跳过本射线16/32/48仍可擦到其他射线的圈像素；图像/JSON 保留真实覆盖率和8邻域连通分量。

实测几何 26607 坐标全部通过。8869 个未镜像组合中，8435 对取整浮点参考零误差，434 最大单轴误差 1 像素（206 仅 x，228 仅 y）；对未取整浮点最大单轴误差 0.5830331204 像素。case 与 UFM 逐点一致，镜像满足 x'=128−x、y'=y。每张截图与独立参考显存逐像素精确比较，PNG 只是 PBM 最近邻放大，没有填补实际 RAM。

原始 P2 结果保留在 `radar/lcd_p2/baseline_3231197.zip`。这些测试不验证物理 5 V 回读安全，也不将仿真 UFM 协议模型视为实物或厂商 primitive 上板验证。
